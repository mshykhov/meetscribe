# ADR-0001: Subprocess isolation for pipeline stages

Status: Accepted
Date: 2026-04-29

## Context

Pipeline meetscribe состоит из нескольких тяжёлых стадий: WhisperX-MLX (Whisper-модель плюс alignment-модель) и Senko (CoreML-бэкенд для diarization). Каждая из этих стадий загружает в RSS память сотни мегабайт - десятки гигабайт весов моделей и активаций.

При последовательном запуске всех стадий внутри одного Python-процесса загруженные модели остаются в памяти до того момента, как Python GC решит их собрать (а часто не собирает вовсе из-за глобальных ссылок в библиотеках). На 16 GB Mac под обычной нагрузкой (IDE, браузер, мессенджеры) это приводит к swap thrashing, и pipeline начинает работать в разы медленнее заявленного времени.

Хелпер `_run_step` (`src/process.py:165-176`) и места его вызовов для transcribe/align/diarize (`src/process.py:210-310`) демонстрируют используемую схему: каждая стадия запускается как inline-скрипт через отдельный subprocess.

## Decision

Каждый шаг pipeline, который загружает ML-модель, выполняется в изолированном subprocess через `_run_step()`. Данные между шагами передаются через JSON-файл во временной директории (`pipeline_data.json`), а не через in-memory структуры.

## Consequences

**Положительные:**
- Детерминированное освобождение памяти при выходе subprocess - ОС возвращает все страницы.
- Per-step timeout enforcement через `WHISPERX_TIMEOUT_SEC` без риска зависнуть в Python-коде.
- Возможность задать разные env vars для разных шагов (`KMP_DUPLICATE_LIB_OK`, `OMP_NUM_THREADS` и т.п.) без влияния на родителя.

**Отрицательные / Trade-offs:**
- Overhead на JSON-сериализацию массивов сегментов (приемлемо: несколько MB на час аудио).
- Inline f-string скрипты внутри `_run_step` тяжело читать, поддерживать и тестировать.
- Невозможен общий in-memory кэш между шагами - каждый subprocess стартует с нуля.

**Что становится возможным дальше:**
- Phase 2 вытащит каждый step в отдельный модуль `src/_step_*.py` и будет вызывать его через `python -m`. Сама изоляция через subprocess сохраняется, но inline-скрипты исчезают, и шаги становятся unit-тестируемыми.
